# Project instructions

- On Windows, prefer Git Bash for shell commands. Use PowerShell only when Git Bash is unavailable or the command is Windows-specific.
- After completing each functional update, run the relevant checks, commit the changes to Git, and push the current branch to its configured remote. Do not force-push. If pushing fails, report the reason and preserve the local commit.
- Before committing, review the staged changes for personal information, machine-specific paths, credentials, and captured conversation data. Keep local configuration, generated bundles, dependencies, and `.probe/` data out of Git.
- Preserve the repository's generic commit identity; do not introduce personal author details without an explicit user request.
